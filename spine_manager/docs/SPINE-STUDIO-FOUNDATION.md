# Spine Studio Foundation

状态：已批准的第一版架构基线，2026-10-29。

## 目标

把现有的复杂 Spine 角色变成可维护、可验证、可回滚、可发布的语义角色系统。

当前 c010 的主目标是：

1. 保留 Spine 4.3.26 工程作为唯一源文件。
2. 让手、背带、枪、脸和特效拥有清晰、独立的控制意图。
3. 让动作可以接触、打断、恢复和确定性重放。
4. 让编辑器、导出文件和 Roomwave runtime 的结果一致。
5. 让优秀 Spine 模型和动作成为可检索的专家案例、结构模式和回归测试。

## 非目标

- 不把 c010 转成 Live2D。
- 不先复制一个大型通用 Agent 框架。
- 不把运行时补丁当成永久骨架修复。
- 不用整理后的 PNG 或 JSON 取代原始 `.spine` 和原始图层。
- 不让 LLM 凭截图或自我解释宣布通过。

## 运行方式

本项目采用 `assistant-operated` 模式。大模型由外部工作台承担，目前就是由 Codex 在对话中承担；项目内不自动调用模型，也不要求用户逐条运行命令。

项目里的 `tools/`、`workflows/` 和 `schemas/` 是确定性工具：它们负责读取素材、生成事实、复制派生工程、执行已决定的修改、导出和验收。大模型负责理解证据、提出方案、解释失败、选择下一步和审查视觉结果。每次我都会先读取上一步产物，再决定是否调用下一个工具。

因此，命令行阶段不是用户操作界面，而是工作台的可复现执行记录。需要时由助手代为执行；你只需要提供源素材、参考模型、目标和必要的视觉判断材料。

## 核心美术原则

### Spine 主干

- 按相对运动、接触和遮挡拆分部件，而不是只按文件夹拆分。
- 控制骨骼、变形骨骼、显示层和物理层分开。
- 手、枪、背带、脸等接触或语义目标必须有独立控制。
- 两段式 IK 的骨骼链、目标和约束顺序是结构设计，不是运行时调参。
- slot、draw order、skin 负责遮挡和换装。
- 刚体、mesh + weights、局部 deform key、physics 各自负责合适的运动。
- 动作按 blocking、timing、curves、layered、secondary motion 的顺序制作。

### Live2D 方法的迁移

- 保留原始分层 PSD，并为动作中会露出的区域补画。
- 用父子层级表达控制范围，父层影响子层，子层不反向污染父层。
- 一个语义通道只表达一种意图，并有 min/default/max。
- 用少量局部 corrective 表达极限角度、脸部和衣物细节。
- 锁定默认形态，并检查参数组合，而不是只检查单个参数。
- 物理是最后一层，必须在主结构通过后按固定 FPS 校准。

## 系统分层

```text
原始资产层
  source/ 与 reference-corpus/，只读、可追溯、带哈希

专家知识层
  knowledge/，保存结构模式、动作模式、失败案例和来源

工作台执行层
  tools/、agents/、prompts/、workflows/，负责计划和确定性执行

证据与发布层
  runs/、evals/、releases/，保存每次运行和最终裁决
```

## 阶段状态机

```text
INTAKE
  -> FORENSICS
  -> SEMANTIC_CONTRACT
  -> RIG_PLAN
  -> DERIVED_MUTATION
  -> MUTATION_EXECUTION
  -> STRUCTURAL_GATE
  -> MOTION_BUILD
  -> VISUAL_GATE
  -> ADVERSARIAL_GATE
  -> PROMOTE
```

阶段之间只通过结构化产物传递信息。失败会回到对应层，不通过增加补丁绕过失败。

## Agent 职责

- `forensic`: 只读分析骨骼、slot、mesh、weights、constraints、atlas 和动画。
- `rig-architect`: 生成语义控制契约和最小可回滚变更计划。
- `executor`: 只在派生副本上执行已批准计划。
- `validator`: 做结构、导出、回读、轨迹和隔离测试。
- `reviewer`: 只看证据包和验收标准，不能读取执行者的自我评价。
- `learning-curator`: 把重复失败整理成工具、Prompt、模式或 Agent 流程改进候选。

第一版不预先创建更多角色。只有回归数据证明现有角色缺少能力时，才增加新角色。

## 证据规则

每次运行都必须记录：

- 输入路径和 SHA-256；
- Spine 编辑器、CLI、runtime 版本；
- Prompt、工具和 Agent 图版本；
- 固定 seed、视口和帧率；
- 计划、变更差异和导出回读；
- 结构、语义隔离、动作、视觉和性能结果；
- FACT、INFERENCE、UNKNOWN；
- 失败分类和停止原因。

硬失败包括共享控制目标、错误 IK 链、导出回读不一致、缺失资源、无法重放和版本不明。硬失败必须阻断发布。

## 进化循环

```text
案例/运行结果
  -> 失败分类
  -> 只提出一个改进候选
  -> 在锁定回归集上重跑
  -> 新结果改善且无回归才保留
  -> 更新知识、Prompt、工具或 Agent 图版本
```

连续三次没有改善时输出 `BLOCKED`，保留最后一个通过版本。

## 第一条纵向切片

第一阶段只回答一个问题：

> 能否在不损伤现有 c010 结构的前提下，永久拆开手部和背带控制，并用 hand-only、strap-only、gun-only 和 hand-to-face 证明它们独立？

先做只读 intake 和取证，再生成派生工程计划。通过之前不继续增加水、泡沫、风扇和更多动作。

## 完成标准

这套架子完成的标准不是文件数量，而是：

1. 能从原始目录生成可追溯清单。
2. 能把优秀模型转成结构模式和测试案例。
3. 能用结构化计划驱动派生工程修改。
4. 能在修改后自动导出、回读和验证。
5. 能把失败反馈给工具、Prompt 和 Agent 版本。
6. 能保留最后一个通过版本，并在无法证明时阻断。
