# Spine 到 Roomwave 的验证与调试闭环

## 每次实验只回答一个问题

不要同时改目标骨骼、权重、约束混合和泡沫位置。每轮只改变一个变量，并给实验一个固定编号。例如：

```text
c010-r03-hand-only-string-off
```

这一轮只回答：“当背带约束关闭时，`ik_arm_r` 是否真的让手移动？”

## 每轮必须保存的证据

```json
{
  "runId": "c010-r03-hand-only-string-off",
  "modelHash": "sha256:...",
  "spineVersion": "4.0.47",
  "runtimeVersion": "4.0.x",
  "seed": 17,
  "preset": "hand-only",
  "time": 1.25,
  "activeTracks": ["idle", "foam_wipe"],
  "changedBones": ["ik_arm_r", "l_arm_2"],
  "changedConstraints": ["ik_arm_r", "string_2"],
  "semanticTargets": {
    "hand": [412, 286],
    "face": [405, 301],
    "strap": [487, 432]
  },
  "expected": "hand approaches face and strap stays within 2px",
  "actual": "..."
}
```

同时保存：

- 带固定颜色标记的截图：绿色真实手、蓝色手目标、黄色背带目标、粉色脸部目标、白色泡沫锚点。
- `frame-trace.jsonl`：每一帧的语义目标、激活轨道和约束混合。
- 关键帧 PNG 或短 GIF：动作开始、接触、回收和回 idle。
- 浏览器控制台错误、页面尺寸、device scale 和运行时版本。

完整证据包必须遵循 `docs/EVIDENCE-PACKET.md`：包含 `run-manifest.json`、`action-spec.json`、模型/runtime hash、clean/debug 成对关键帧、`frame-trace.jsonl`、`console.jsonl`、`metrics.json`、五个独立角色的 `role-review/*.json`、`adjudication.json` 和 `regression.json`。截图、轨迹和日志必须来自同一次运行。

房间级回放之后运行 `npm run trace:analyze`。它把产品房间的固定 seed trace 转成可比较的动作报告，明确区分“目标移动”“可见手跟随”“目标与可见手的接触误差”和“背带是否串动”。报告中的数值是 `FACT`，`interpretation` 只是待视觉复核的归因线索；不能把它直接当成动作自然度通过。

动作矩阵的五个按钮要分两层验收：先用 smoke 确认语义发射、话术和路由，再为需要判断自然度的动作采集同一 run 的关键帧、效果锚点和逐帧 trace。smoke 通过而没有对应视觉证据时，结论只能写成“语义已验证、视觉未验证”。中断和重复点击同样要把输入时刻、被替换的动作、恢复 idle 采样写入证据包，不能只在测试进程内断言。

每条结论分成三类：

- `FACT`：工具直接读到的骨骼、约束、像素或轨迹事实。
- `INFERENCE`：视觉模型或 LLM 根据关键帧提出的解释。
- `UNKNOWN`：当前证据无法判断的内容。

只有 `FACT` 和经过独立证据支持的 `INFERENCE` 才能进入下一阶段；`UNKNOWN` 必须转成新的最小实验。

## 调试顺序

1. **结构层**：模型和 atlas 能否加载，名字是否存在，版本是否一致。
2. **约束层**：目标移动时，实际受控骨骼和间接受影响插槽是否符合预期。
3. **动作层**：轨道混合、优先级、打断和回 idle 是否稳定。
4. **素材层**：纹理缺口、穿插、手指和袖口是否在极限姿势下暴露。
5. **产品层**：Roomwave 按钮、Solo/Together、效果锚点和性能是否通过。

## 四道完成门

1. **G1 确定性运行和语义门**：加载、版本、路由、按钮、动作存在、控制台、共享目标和回 idle 全部通过。
2. **G2 动作与时间门**：准备、加速、接触、停留、回收、打断和恢复都有可解释的关键帧与轨迹，动作意图一眼可读。
3. **G3 结构、服装和材质门**：衣服、背带、枪械、头发、关节、网格、遮挡、透明边缘、材质和角色身份没有明显破坏。
4. **G4 人类视觉观感门**：动画师、技术美术、视觉导演、产品审查者和对抗审查者分别评分，裁决者确认没有重大分歧或未解决的 `UNKNOWN`。

G1 到 G3 的硬失败不能被视觉模型的高分抵消；G4 的低置信度和分歧不能被平均分掩盖。

视觉评估放在动作层和素材层之间：它同时看全局身份、局部结构、关键帧时间关系和语义接触，但不覆盖结构硬门槛。具体评分格式见 `VISION-REVIEW-RUBRIC.md`。

如果截图里“看起来动了”，先不判断好坏，先查 trace：是目标骨骼动了、手骨骼动了、网格顶点动了，还是背带约束把插槽带动了。

当前 c010 已经用 `c010-hand-reachability.json` 把这一步具体化：目标点位移约 140.5px，可见手部 `l_hand_1` 只位移约 8.2px，目标与可见手部在接触阶段相距约 134.4px。因此这不是“目标点已经等于手”的通过证据，而是 `unreachable_ik` 阻断；没有可编辑工程时只能保留运行时语义试作，不能把它发布成触脸动作。

## 让自动分析读得准

给分析者的最小输入不是一张普通截图，而是“截图 + 实验描述 + 轨迹”。每次反馈最好包含：

```text
模型：c010_00 / hash
运行时：Spine 4.0.x
预设：hand-only
时刻：1.25s
目标：手到脸，背带不动
实际：背带移动 31px，手移动 4px
证据：frame_075.png + frame-trace.jsonl
```

固定相机、缩放和标记颜色；不要一轮换一个画布比例。这样可以区分绑定错误、约束串动、素材缺口和单纯的视觉错觉。

视觉复核必须采用多角色盲审。评审者只看动作规格、参考图和证据包，不看生成者的解释；每条发现都要标注 `FACT`、`INFERENCE` 或 `UNKNOWN`，并引用 `frame`、`time` 和 `region`。任一维度分歧超过 1 分、置信度低于 0.8 或结论相互矛盾时，进入复评；仍无法解释就标记 `blocked_visual_uncertainty`。

## 通过门槛

| 层级 | 通过条件 |
|---|---|
| 结构 | 所有语义绑定都能解析；没有未声明的共享目标 |
| 手部 | hand-only 中手目标误差在可接受范围，背带位移低于阈值 |
| 背带 | strap-only 不改变手腕位置；动作回收不拉断纹理 |
| 动作 | 中断、重复点击、回 idle 都无跳帧或卡轨道 |
| 效果 | 泡沫锚点跟随语义位置，不跟随偶然插槽 |
| 交付 | Playwright 回放、截图差异、独立审查 Agent 都通过 |

发布前必须同时满足四道门。调试闭环固定为：冻结模型/版本/视口/seed → 写一个可证伪假设 → 只改变一个变量 → 固定输入回放 → 先跑 G1 → 采集关键帧、trace、日志和指标 → 多角色盲审 G2/G3/G4 → 裁决并归档 → 通过则冻结版本，失败则按错误标签进入下一轮。连续三轮没有改善就停止自动修复并报告阻断原因。

## 外部证据

结果不只靠我和用户的肉眼判断。可以交叉使用：

- Spine 编辑器的 IK、Weights、Mesh Tools 和 Preview 视图。
- 自动化浏览器回放和无控制台错误检查。
- 约束图和逐帧 trace 的数值检查。
- 固定 seed 的截图差异和关键点距离统计。
- 另一位动画师或程序员只看验收包做盲审。

## 房间级工具沉淀

`configs/room-action-matrix.json` 先固定动作、目标、效果和验收条件；后续房间检查工具按同一份矩阵验证路由、按钮、状态和锚点。每次回放都保留固定视口截图、trace、控制台日志和与基线的差异，避免把一次偶然的浏览器画面误认为模型能力已经稳定。
