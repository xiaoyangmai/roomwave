# Codex 编排方式

本项目不在仓库内运行常驻的大模型 Agent。当前工作方式是 `assistant-operated`：Codex 主代理承担编排和裁决，Codex 子代理承担一次性的专家咨询，项目脚本承担确定性执行。

## 四层职责

```text
用户目标
  ↓
Codex 主代理：拆目标、创建 run、分派专家、决定下一步、最终裁决
  ↓
Codex 子代理：Spine、美术、Live2D、动作、运行时和对抗审查
  ↓
项目工具：取证、复制、mutation、导出、回读、指标检查
  ↓
Spine 工程、渲染帧、运行轨迹和结构化证据
```

主代理是唯一的状态机操作者。它负责读取 `run-state.json`，决定是否进入下一阶段，并向用户汇报。子代理不是常驻服务，也不直接推动状态机。

本机 MCP server 和项目内 Agent runtime 是两件事：前者只是 Codex 的外部工具，后者是项目自己启动模型和调度进程。我们采用前者时，工具可以安装在本机并注册给 Codex；项目仍然只保存输入、输出和回归证据。

## Codex 机制和项目对象的对应关系

| Codex 机制 | 项目对象 | 用法 |
|---|---|---|
| 主线程 | `run-state.json`、最终裁决 | 持有完整上下文，串行推进阶段 |
| `collaboration.spawn_agent` | `agents/` 中的角色模板 | 委派一次性的只读专家任务 |
| `collaboration.wait_agent` | `runs/<run-id>/agent-notes/` | 回收专家报告，等待所有独立意见 |
| `functions.exec` | `tools/`、Spine CLI、验证器 | 执行确定性步骤，不让模型直接改二进制工程 |
| 本机注册的 MCP server | 外部 Spine 工具适配器 | 由 Codex 按需调用，安装在本机，不属于项目运行时 |
| `cua` / 截图工具 | 视觉证据包 | 由主代理统一操作编辑器和画面 |
| `web` | 外部官方文档和参考项目 | 由主代理或研究代理查证来源 |
| `knowledge/`、`prompts/` | 长期经验 | 只能在一轮裁决后由主代理整理更新 |

## 每一轮的实际顺序

1. 主代理创建唯一 `run-id`，执行 intake 和 forensics，得到事实报告。
2. 主代理把指定的证据文件、范围、停止条件和输出格式发给多个只读子代理。
3. 子代理分别输出 `FACT`、`INFERENCE`、`UNKNOWN`、`BLOCKER` 和 `NEXT_ACTION`，不能修改源工程、共享派生目录或其他代理的文件。
4. 主代理比较意见，生成唯一的 semantic contract 和 rig plan。意见冲突时保留冲突，不用投票掩盖未知。
5. 主代理串行调用确定性 mutation 工具。每次尝试使用独立的 `mutation-candidate` 目录，失败也不覆盖以前的尝试。
6. 结构验收通过后，主代理生成统一的视觉证据包，再并行委派结构、视觉和对抗审查代理。
7. 审查代理只看证据包和评分规则，不看执行者自评、主代理倾向或其他审查结论。
8. 主代理依据全部报告做 adjudication，决定 repair、repeat、promote 或 `BLOCKED`，并把失败归因写回本次 run。

## 写入纪律

共享工作区不等于可以并行写同一个目录：

- 子代理默认 `read-only`，只允许在自己声明的 `agent-notes/<role>.json` 写入；也可以直接返回报告，由主代理写入。
- `source/` 永远禁止子代理写入。
- `runs/<run-id>/derived-source/` 和 `mutation-candidate-*` 只能由主代理串行调用确定性工具写入。
- Spine GUI 只能由主代理操作，避免多个代理抢同一窗口。
- 需要修改代码时，先由主代理决定范围；大型代码修改才考虑独立 worktree，不能用共享目录并行覆盖。

## 独立审查的含义

独立不是换一个永久模型，而是隔离上下文。审查代理使用新的 Codex 子任务，只收到同一份 evidence packet 和对应 rubric；不传递执行者解释、主代理猜测和其他审查结果。这样可以减少锚定，但最终仍由主代理保留原始报告并裁决。

## 为什么不让模型直接改 Spine

模型适合解释结构、提出方案、比较候选和判断画面。Spine 工程修改、导出、回读和哈希检查必须由确定性工具完成。这样每一次模型建议都会变成可审查的 JSON 计划，每一次实际修改都有派生目录、差异和回读证据。

## 失败和进化

连续失败不通过增加临时补丁绕过。主代理把失败归类为数据、结构、工具、动作、视觉或编排问题，只提出一个改进候选，在锁定回归集上重跑；没有证据证明变好就保留旧版本并阻断。
