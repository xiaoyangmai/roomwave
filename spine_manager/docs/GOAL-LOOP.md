# c010 gaming_c010 Goal 执行协议

这个文件把“持续推进”变成可检查的工作协议。最终产品目标不是单独展示模型，而是做出一个可玩的 `gaming_c010` 直播间：它复用原 Gaming 的直播结构和交互语义，由 c010 Spine 驱动角色；同时把调试、回放和证据工具沉淀成以后换角色也能复用的工作流。Goal 由用户手动开启；开启后，每一次用户与 Agent 的有效往返记为一轮。Agent 不把页面能显示当作完成，而是根据下面四个状态推进。

## 完成状态

| 状态 | 含义 |
| --- | --- |
| `runtime-usable` | 当前 4.3.26 导出物能在 Roomwave 冷启动后的 `gaming_c010` 页面中加载，共享 Gaming 交互契约和语义按钮可用。 |
| `mutation-ready` | 项目内的 Spine 编辑器或 CLI 能打开可编辑工程，并完成受控派生导出。 |
| `migration-validated` | 4.3.26 候选工程已经独立保存、导出，并由匹配的 4.3 runtime 回载验证。 |
| `release-ready` | 手部、背带、道具、纹理、视觉、版本、启动和回滚证据全部通过。 |

当前目标基线是 4.3.26；4.0.47 只作为只读源和回滚轨。迁移完成前，Roomwave 仍暂时回载旧 4.0.47 导出物，不能把它误称为已完成的 4.3 运行验证。

房间集成的里程碑改为：默认 Solo 房间固定保留原版 `gaming-seated` 作为对照；`/solo/?room=gaming_c010` 是正式产品入口，承载 c010 角色和接近原 Gaming 的直播交互；`/solo/?spine=c010` 保留为兼容入口；`/spine-audit/c010/` 只负责模型审计和动作试作。旧版 `gaming` 房间保留为可直达对照页，不和新房间混用。房间接入必须通过 `LiveRooms`、按钮回放、效果锚点和冷启动证据验证，不能只用单页 Spine 试作页证明完成。

## 每轮操作

Goal 开启后，Agent 在每轮开始记录一次：

```powershell
npm run goal:turn -- --turn 1 --summary "本轮要回答的一个问题" --priority "最高优先级"
```

轮次必须连续递增。第 5、10、15 轮等在记录本轮前自动执行 `checkpoint-review.mjs`。检查点会重新读取方案文档、控制配置、纹理门槛、校准状态和最近流水线证据，记录文件哈希、当前阻断、下一优先级和是否允许修改/发布。

流水线开始时先运行 `deps:ensure`。它只在 Node 包或 Pillow 缺失、版本超出配置范围时安装，并把探测结果与安装命令写入 `artifacts/dependency-check.json`；已有正确版本不会重复安装。后续检查点会把这个文件当作依赖证据。

`smoke:runtime` 还会写入房间路由和动作证据，固定记录 `gaming_c010`、默认 `gaming-seated` 和旧版 `gaming` 对照页是否可加载；它和结构/视觉证据一样，不能用旧的独立展示页或覆盖层结果代替。

如果检查点缺文件或证据缺失，检查点本身会 fail-closed；如果视觉复核仍待定或硬门槛未证明，检查点会记录 `gatesClosed: true`。这不会阻止继续做修复实验，但会阻止进入 mutation/release 合并步骤。

## 每五轮复盘内容

复盘必须回答四个问题：

1. 当前状态属于 `runtime-usable`、`mutation-ready`、`migration-validated` 还是 `release-ready`？
2. 最近五轮哪个失败标签重复出现，数值是否真的改善？
3. 机器指标、逐帧轨迹和独立视觉评估是否一致？如果不一致，下一轮只做一个最小实验。
4. 下一优先级是什么，完成它需要哪一个新证据？

视觉模型只能补充动作可读性、接触合理性、遮挡和身份观感。mask 外变化、alpha 污染、崩溃、版本错配、未声明共享目标和运行时回归仍由确定性检查直接阻断。视觉评分待复核不能写成通过。

## 两条版本轨

- **回滚轨**：4.0.47 编辑/导出 + 4.0.x runtime，只读保留并继续作为回滚点。
- **基线迁移轨**：项目内 `tools/spine-4.3.26/SpinePortable.exe`，只写入独立 4.3 派生目录；必须完成保存、CLI/编辑器导出、4.3 runtime 回载和全套重验后，4.3.26 才能成为实际运行基线。

任何迁移失败都回到 4.0.47 回滚轨，不能覆盖 4.0.47 源工程、旧导出物或语义绑定。

## 目前的真实结论

`gaming_c010` 已达到旧资源下的 runtime-usable；当前新基线迁移尚未达到 `mutation-ready`，因为 4.3.26 CLI 导出探针要求 activation code。只有独立 4.3.26 工程保存、导出并由 4.3 runtime 回载后，才能进入 `migration-validated`。当前模型发布阻断仍是：一段式手部 IK、背带共享目标、4.3 导出尚未完成、独立视觉复核仍有 UNKNOWN，以及纹理身份/材质评分仍为 deferred。
