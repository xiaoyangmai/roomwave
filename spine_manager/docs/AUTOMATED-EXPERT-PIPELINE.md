# 无人工修整的专家级流水线

## 先说边界

“你不参与人工修整”可以实现，但不能把它理解成“模型永远不会失败”。正确做法是把人工步骤替换成一组互相独立的生成器、检查器和审查器；当证据不足时，系统必须输出“无法证明”，停止发布，而不是让 LLM 凭感觉挑一张看起来更好的图。

这比单纯增加模型、增加动作或增加生成候选更深入：每一阶段都要有输入契约、只允许写入自己的产物目录、可重复的命令和明确的通过门槛。

## 本轮方案复盘后的补充约束

现有编排器已经把每个阶段的日志写入 `artifacts/runs/<runId>/`，但部分历史工具仍会更新 `configs/` 和 `evidence/` 下的共享派生文件。因此当前实现必须被理解为“阶段日志隔离、派生证据共享、发布仍需合并门禁”，不能把共享文件直接当作独立 Agent 产物。真正进入发布目录前，Release 阶段必须重新读取本次 run 的 manifest、哈希和证据引用。

完成定义拆成四个状态：`runtime-usable`、`mutation-ready`、`migration-validated`、`release-ready`。每个状态还要记录四道完成门：G1 确定性运行和语义、G2 动作与时间、G3 结构/服装/材质、G4 人类视觉观感。当前 c010 只有旧的运行时试作证据；4.3.26 只读打开不等于迁移验证，纹理身份/材质和多角色视觉复核仍是 deferred，也不能写成通过。

另外，启动验证分成两层：`startup-smoke` 在临时端口冷启动后端并检查 Solo、Spine 和审计路由；`runtime-smoke` 再在已有或专用服务上进行浏览器动作回放。两者缺一不可。

每五轮复盘由 `configs/goal-loop.json` 和 `tools/checkpoint-review.mjs` 固定执行。检查点重新读取方案文档、版本策略、门槛配置、校准状态和最近证据；缺文件、证据过期、视觉不确定或硬门槛未证明时 fail-closed。具体操作见 `docs/GOAL-LOOP.md`。

流水线的依赖阶段先检查项目声明的 Node runtime 和 Pillow 版本；只有缺失或越界时才安装，并把版本、命令和结果写入依赖证据。依赖检查通过不代表模型或视觉门槛通过，它只证明后续确定性工具具备可重复的执行环境。

## 顶尖专家会做、但通常不会被需求写出来的工作

1. **资产取证**：确认每张纹理、每个导出文件、每个动作参考的来源、版本和许可，避免把推断出来的拆层当成原始素材。
2. **控制接口设计**：先定义手、背带、道具、脸和效果的语义接口，再决定骨骼怎么命名；不让 Roomwave 绑定模型内部名字。
3. **副作用审计**：枚举每个 IK、Transform、Physics 约束会影响哪些骨骼、插槽和效果锚点；检查一个目标是否被多个语义角色复用。
4. **动作矩阵**：为每个 Roomwave 按钮定义休息位、接触位、极限位、打断和恢复，而不是只做一条演示曲线。
5. **失败预算**：规定最多修复轮次、最低分数、最大像素误差和版本兼容条件；不满足就阻断交付。
6. **独立验证**：生成器不能给自己评分；结构检查、运行时回放和视觉审查使用不同过程，结论必须指向具体帧和数值。
7. **回放与回滚**：固定 seed、模型 hash、工作流、mask、运行时和相机参数，任何一个结果都能重建或回退。

## 从最原始的素材开始

| 素材 | 用途 | 没有时的处理 |
|---|---|---|
| `.spine` 工程、编辑器版本、导出设置 | 真正修改骨骼、IK、权重和约束 | 创建可编辑派生工程，不改二进制猜测 |
| 分层 PSD/KRA/原始绘图文件 | 得到手、袖口、背带、道具的独立透明层 | 从 atlas/slot 拆分并标记为推断层 |
| 原始 atlas、region、slot、attachment 清单 | 保持纹理与 Spine 名称对应 | 用 JSON/运行时审计重建映射 |
| 角色转面图、服装结构图、材质色板 | 约束补画的身份和服装细节 | 从现有高分辨率图提取参考板 |
| 动作视频或关键帧草图 | 定义接触点、遮挡和运动范围 | 由现有 Spine 动画采样关键帧 |
| 手掌朝向、握持道具、触脸等局部参考 | 只补真正需要的角度 | 先改动作路径，减少需要补画的角度 |

## 方案选择

### 方案 A：Spine 原生派生工程（推荐长期方案）

拿到 `.spine` 后，在原骨架上增加独立 `hand_target`、`strap_target`、`gun_target` 和效果锚点，再用 Spine CLI 批量导出。控制能力最高，能保留运行时 IK、混合和次级运动；前期需要整理源工程。

### 方案 B：运行时审计 + 自动补图 + 派生工程（当前可立即推进）

继续使用现有 `.skel/.atlas/.png` 做约束审计和动作设计，同时把 atlas 拆层、自动生成局部纹理，然后导入一个派生 Spine 工程重建控制层。它不修改原始资源，适合当前 c010。

### 方案 C：指定动作的预渲染 fallback

如果始终拿不到可编辑工程，或自动补图无法通过硬门槛，则为 `foam_wipe`、`fan_hold` 等少数动作生成透明帧序列，作为动作级 fallback。它牺牲任意目标点和实时 IK，换取可证明的画面稳定性。不能把它伪装成通用 Spine 控制。

建议采用 A+B，C 作为明确的兜底，不把项目卡在“必须先完成全角色重建”。

## Agent 编排

每个 Agent 只接收结构化输入，只写自己的 `artifacts/<stage>/<runId>/`，不能直接修改全项目。发布 Agent 只能合并已经通过阶段门的产物。

| Agent | 只负责什么 | 输出 |
|---|---|---|
| Forensic | 读取模型、atlas 和版本，生成骨骼/插槽/约束图 | `model-manifest.json`、`constraint-graph.json` |
| Rig Planner | 根据语义需求提出新增目标、IK、Transform 和权重计划 | `rig-plan.json`，不直接改模型 |
| Texture Producer | 自动拆层、生成局部候选、做透明和颜色清理 | 候选图、mask、生成元数据 |
| Mutator | 只通过 Spine CLI/JSON 和受控图像模型适配器修改派生工程 | `derived.spine`、JSON、导出物 |
| Runtime Runner | 用固定相机和 seed 回放动作，采集关键帧和 trace | `frame-*.png`、`frame-trace.jsonl` |
| Adversarial Reviewer | 专门寻找左右手错误、共享目标、穿插、版本错配和未声明副作用 | `review.json` |
| Release | 只合并所有 gate 通过的版本 | 发布 manifest、回滚指针 |

生成 Agent 和评分 Agent 必须分离。评分 Agent 不读取生成 Agent 的解释，只看需求、输出和证据；这样不会因为“生成者说它已经修好了”而降低标准。

每个 Agent 的提示词都固定写出：允许读取的目录、允许调用的工具、禁止修改的文件、输出 JSON schema、通过条件和失败标签。LLM 不直接阅读巨大的原始审计 JSON，而是读取 Forensic 生成的摘要、约束边和指定关键帧。视觉角色的输入和输出必须遵循 `docs/EVIDENCE-PACKET.md` 与 `configs/visual-review-roles.json`。

一个 Agent 的任务模板应固定成下面的结构：

```text
角色：只负责哪一阶段
输入：文件、schema、模型 hash、上一阶段摘要
允许工具：只列本阶段需要的命令
允许写入：artifacts/<stage>/<runId>/
禁止动作：不改原始资源、不跳过验证、不读取生成者解释
输出：严格 JSON + 证据文件列表
通过条件：数值门槛和必须存在的证据
失败标签：可枚举的错误类型
```

这样做的作用是把 LLM 的开放式判断限制在“提出假设、选择实验、解释证据”三件事上；文件修改、图像比较、版本检查和回放都交给确定性工具。

## 无人工补图闭环

1. **拆层**：优先使用透明 atlas 的 alpha、slot/attachment bounds 和 mesh 直接生成 mask；只有输入是没有透明层的外部图时，才允许图像模型提出候选 mask，再用 alpha 连通性和边界检查修正。
2. **设定目标姿势**：由 Rig Planner 从动作轨迹计算手腕、肘和接触点，不让生图模型自行猜姿势。
3. **批量局部生成**：通过统一的 `image-model-edit-api` 适配器提交原图、mask、参考图、姿势说明和多个候选请求；只重绘遮罩区域。适配器必须保存模型快照、请求参数、响应 ID 和输出 hash。
4. **自动清理**：用 OpenCV/Pillow 做 mask 内合成、alpha 去边、透明边缘收缩、颜色采样和尺寸统一；不把背景或 mask 污染带进 atlas。
5. **硬检查**：透明边缘无非预期连通区域，尺寸和色彩范围合规，手指区域没有严重断裂，生成图能回填到同一个 Spine 网格。
6. **软检查**：独立视觉审查器对身份、服装、手势、遮挡和材质一致性打分；低置信度一律拒绝。
7. **Spine 试绑**：把候选图放入派生工程，自动绑定权重并渲染极限姿势；检查手腕误差、网格拉伸、插槽遮挡和背带串动。
8. **有限修复**：只针对失败类别重跑对应阶段，最多三轮。三轮没有提升，就标记 `blocked_missing_source` 或 `blocked_no_editable_project`，停止发布。

这一流程不要求用户挑图。系统只会自动接受同时通过硬检查和独立评分的候选；否则继续生成、换 fallback，或明确报告无法证明。

## 用 LLM 做到“像专家”

LLM 最适合做解释、假设和调度，不适合直接修改二进制模型或凭截图判断约束关系。每轮按照下面的顺序执行：

```text
读取结构化证据
  -> 提出一个可证伪假设
  -> 选择一个最小实验
  -> 调用确定性工具
  -> 采集 trace / 关键帧 / 日志
  -> 独立评分
  -> 通过则冻结版本，失败则按错误标签进入下一轮
```

LLM 必须在输出中引用 `artifact`、`frame` 和 `time`，不能只写“看起来更好了”。错误标签至少包括：

```text
shared_target
wrong_hand_side
unreachable_ik
mesh_stretch
alpha_bleed
identity_drift
version_mismatch
missing_source
runtime_regression
```

相同错误连续三轮没有改善，Agent 应停止并报告阻断原因。它不能为了完成任务继续猜改文件。

## 证明结果正确的证据

除了我和用户，还需要这些独立证据：

- Spine CLI 导出、JSON 往返和官方 runtime 独立加载。Spine 官方明确建议用 CLI 自动导出，并说明编辑器版本与 runtime 版本必须匹配：[Export](https://us.esotericsoftware.com/spine-export/)。
- 约束图静态检查：手部目标不能和背带目标共享，所有语义名称必须能解析。
- 无头浏览器或 CanvasKit 回放：固定相机、固定 seed、固定时间点，采集关键帧和控制台日志。
- 数值检查：手腕到目标的距离、背带像素位移、alpha 外溢、网格顶点位移、帧率和加载时间。
- 独立审查 Agent：只看证据包，不看生成理由；可以使用多评分器或 Python 检查器组合分数。OpenAI 的 Graders 支持规则检查、Python、模型评分和 MultiGrader 组合：[Graders](https://platform.openai.com/docs/api-reference/graders/label-model?lang=python)。
- 版本回放：同一模型 hash、工作流 hash 和 seed 必须得到同样的 manifest 和关键帧摘要。

房间动作的证据包还必须包含 clean/debug 成对关键帧、动作规格、逐帧轨迹、控制台日志、数值指标、五个独立角色评审、裁决结果和上一版回归差异。评审角色不能读取生成理由，生成角色不能根据评审理由直接改写同一轮产物。

## 大模型能力应该放在哪里

大模型最有价值的地方不是替代所有规则，而是补上“人类观感和语义意图”这一层：

- 判断动作是否一眼可读，手是否真的像在接触脸或泡沫。
- 发现规则难以表达的遮挡、姿态别扭、身份漂移和风格不一致。
- 根据具体帧和时间点提出最小整改建议。
- 在多个候选之间做带证据的比较，而不是只挑最高总分。

这层必须采用全局、局部、时间、语义四级评分，并至少由两次独立视觉评估组成。视觉模型的结论只能作为软门；mask 外变化、alpha 污染、崩溃、版本错配和未声明共享目标仍由确定性规则直接阻断。

## 阈值如何校准

`texture-gates.json` 中的数值是护栏，不是永恒真理。校准流程使用原始 `idle` 和已通过关键帧作为正样本，再自动注入 mask 外泄、颜色漂移、背带跟手、权重拉伸和时间跳帧等已知坏样本，按错误标签分别估计阈值。

阈值变化必须写入 `calibration.json` 的变更记录。Agent 不能为了让当前候选通过而临时放宽阈值；优先控制误接收，软指标才允许根据样本分布调整。

## 主动学习和最小整改

每轮优先处理最接近门槛、视觉评分分歧最大或机器指标与观感冲突的样本。整改必须从错误标签映射到最小动作，例如：

```text
shared_target -> 隔离 string_2 目标 -> 只重跑 hand-only
alpha_bleed -> mask-only composite + alpha cleanup
mesh_stretch -> 限制权重影响或重新绑定局部网格
temporal_jump -> 调整轨迹采样或回退上一候选
```

如果同一错误三轮没有改善，或两套视觉评估无法达成一致，就停止并标记 blocked，要求新增原始素材或可编辑 `.spine` 工程。

## 四道门完成定义

只有四道门都通过才发布到 Roomwave：

1. **G1 确定性运行和语义门**：没有未声明的共享控制目标，路由、版本、动作、效果锚点和回 idle 通过。
2. **G2 动作与时间门**：`hand-only`、`strap-only`、`gun-only`、动作接触、打断和恢复通过数值与逐帧检查。
3. **G3 结构、服装和材质门**：衣服、背带、枪械、头发、遮挡、网格、材质和身份没有重大破坏。
4. **G4 人类视觉观感门**：五个独立视觉角色和裁决者没有重大分歧，所有结论都能回指证据帧。

所有失败轮次和最终选择都必须有证据；无法证明的部分标记为 `UNKNOWN` 或 `blocked_visual_uncertainty`，不能隐藏。
