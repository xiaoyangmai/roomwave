# c010 运行配置、有限行为与演练

状态：2026-11-04。范围是当前 AIRI / Spine WebGL 单页演出实例，使用 c010 ZIP。人物加载、输入、动作和暂停恢复在本页完成；产品房间由 Roomwave 模块负责。真实 LLM、TTS 和素材生产不属于本模块。

## 配置与职责

`src/stage/c010.ts` 是本入口的角色运行配置。`src/stage/stage.vue` 消费资源、视图和动作映射；`src/stage/conversation.ts` 从同一份反应映射选择支持的 ACT 情绪，`StageEmotion` 类型也由映射的键推导。

| 配置 | 当前值与用途 |
|---|---|
| `id` | `c010`，标识当前角色 |
| `model` | `/c010.zip`，skin `00` |
| `idle` | `idle`，循环播放 |
| `reactions` | `think → think`、`happy → delight`、`angry → angry` |
| `speech` | `talk_start` / `talk_end`，由实际音频开始和结束驱动 |
| `foam` | `foam_wipe`、四个 Foam 事件、`foam_face_anchor` / `foam_palm_anchor` |
| `mixSeconds` | `0.2` 秒，沿用之前 AIRI 的默认混合时长 |
| `view` | 960×720 初始画布、30 fps 绘制上限、Vite 直接引用现有阳台背景 |

实际画布尺寸由现有布局和 AIRI 适配；30 fps 是绘制上限，不是性能保证。当前运行时不采集或发布媒体流。缩放、坐标和播放速度仍使用既有默认值。

`src/stage/stage.vue` 使用已有 VueUse 的尺寸观察，把舞台实际宽高传给 AIRI 的自适应逻辑。窗口缩窄后重新适配人物比例，避免只缩画布而裁掉角色；没有增加独立帧循环。

本文件是运行时如何使用素材的配置，不替代内容生产的 Character Pack、许可或发布记录。Canvas 的 `foam_wipe` 已接入约 3.6 秒的真实 clip，水和风仍使用原配方。资源模块负责源工程、导出和 ZIP 内容。

加载完成时，`onModelLoaded()` 一次检查真实模型的动画清单与 skin：

- 必须精确存在 `idle`、三个反应、`talk_start`、`talk_end` 和 skin `00`。
- 缺少时显示具体名称，保持 `ready=false`、会话暂停、恢复互动与动作按钮禁用。
- 不使用 AIRI 的近似名称匹配掩盖缺失。例如只有 `delight_extra` 不能满足 `delight`。
- 内部输入沿用 TypeScript 类型流转，不在每次播放时重复检查资源清单。

## 状态与轨道

这三个状态各自有明确来源：

| 状态 | 来源 | 含义 |
|---|---|---|
| 互动可用 | `active` | 是否接收本页动作与文字输入 |
| 对话阶段 | `conversation.phase` | 等待回答、接收文字、播放语音或对话空闲 |
| 实际动作 | AIRI `getPlaybackState()` | 当前 Spine 轨道中的动画、时间和权重 |

AIRI 当前适配器固定使用 track 0 基础待机、track 1 单次反应或擦脸、track 2 说话。轨道分工属于适配器约定，未增加可任意改写轨道的配置。

擦脸先中断当前回答与声音，再通过 `playAction('foam_wipe')` 播素材内动画，完成由同一 AIRI 轨道监听混回 idle。情绪、重复擦脸、新输入或暂停均可替换/结束它。加载时独立检查动作、四个事件和两个锚点；缺少擦脸资源只禁用擦脸，不影响已通过检查的基础演出。泡沫在 `FoamNotice` 后出现、`FoamContact` 后减少、`FoamCleared` 清空，`FoamComplete` 收手结束；外部 Canvas 跟随 Model 的渲染回调与只读骨骼屏幕坐标，不修改动画骨骼。

调试入口 `roomwaveStage.seekFoam(seconds)` 暂停并定位当前真实动画，`resumePreview()` 恢复。`snapshot()` 含 `actionReady/actionIssue/foam`，trace 记录真实 Foam 事件；这些用于预览和验收，不是产品调度接口。

开心和生气等属于完整角色反应，不是独立脸部层。沿用有限组合：基础待机加一个反应；实际音频可以驱动既有说话轨道。固定音频与开心叠加沿用回归覆盖，不宣称所有动作或任意权重组合都已完成视觉验收。

## 有限行为规则

规则就近实现于 `src/stage/stage.vue` 的 `applyPerformance()`，没有另建调度器。AIRI 继续负责动画混合、TrackEntry 完成和自然混出。

| 输入与当前条件 | 执行 | 结束方式 |
|---|---|---|
| 新消息 | 取消旧轮次，清旧反应与声音，开始新思考 | 首段文字结束思考，或显式反应替换 |
| 支持的反应，当前没有相同动画 | 在 track 1 播放一次 | 完成后由 AIRI 混回 idle |
| 相同反应仍在播放 | 保持当前 TrackEntry、播放时间和原权重 | 不延长、不排队、不重新起播 |
| 不同反应到达 | 按 0.2 秒混合切换，以新反应为当前动作 | 新反应自然收尾 |
| 相同反应已经结束，再次收到 | 重新播放一次 | 正常收尾 |
| 首段普通文字／无正文回答结束 | `clear-emotion(onlyIf: think)`，只在当前仍为思考时清除 | 不清掉期间手动触发的开心或生气 |
| ACT `neutral` | 清除当前反应，不限制名称 | 文字生成继续，音频不受此信号影响 |
| 正文与语音队列完成 | 对话进入 `idle`，保留已开始的显式反应 | 等反应自身完成 |
| 中断／失败／暂停／切换演练 | 沿用会话取消与 `reset`，清反应并结束嘴部 | 动作混出；暂停还禁用输入 |

手动按钮和 ACT 共用相同反应规则。不同反应按到达顺序切换，本轮没有增加运营优先级、等待队列或随机动作。重复反应即使强度变化也保持原权重；要更换权重需先结束或清除该反应。

重复判断读取实际 track 1，而不是另存“最后一次情绪”。因此动画结束后再次收到相同情绪仍能播放。默认思考的条件清除也是读取这一轨道，避免文字到达时误清观众刚触发的其他反应。

自然完成沿用 AIRI 的当前 TrackEntry 所有权检查。旧轮次输出仍由现有聊天取消和 `turnId` 检查挡住，本轮不增加另一套取消机制。

`window.roomwaveStage.snapshot()` 新增 `profile`；`trace` 的信号记录新增 `decision: apply | keep-current`。这表示本地信号入口作出的决定，实际执行仍应结合 `tracks` 判断，不是远端指令执行回执。

回 idle 的验收条件仍是 track 0 为 `idle` 且 track 1/2 已为空。仅看对话的 `phase=idle` 不足以证明动作已经结束。

## 演练入口与场景

演出端“对话联调”中选择“演练场景”，点击“开启本机脚本演练”，再发送任意文字。切换下拉选项本身不会改变当前演出；点击开启才应用场景并清空本次会话。当前生效场景显示在模式名称中。

| 场景 | 固定输入序列 | 应观察到的行为 |
|---|---|---|
| 基础：逐字回答 | 原有分块 ACT 与逐字文字 | 思考、开心、文字、中断与下一轮 |
| 重复开心：保持当前动作 | 开心后间隔 400 ms，再发送两次开心 | 三个信号，一次起播，随后自然回 idle |
| 开心 → 生气：切换反应 | 开心后 900 ms 切生气 | 混合切换，生气完整收尾 |
| 文字先结束：动作自然收尾 | 开心标记与一条短文字，立即结束生成 | 文字显示完成时开心仍在播放 |
| 开心 → 恢复：继续回答 | 开心后 900 ms 发 neutral，再继续文字 | 清反应但不结束回答 |

每个场景都通过 `ConversationAdapter.stream → AIRI ACT 解析 → PerformanceSignal → 实际 Spine`，不从演练代码直接调用动画。场景间隔只安排输入到达时间，动作完成依赖真实 TrackEntry，未使用估算定时器宣布动作结束。

这些是固定脚本，不调用模型服务、不合成语音。没有音频时嘴部不动；“播放测试语音”仍独立使用原有 WAV。

中断、新轮次替换和暂停恢复直接使用本页按钮与输入框。暂停会中断当前内容但保留模式与历史，恢复后等待新输入；无需推流或房间服务。

## 验证

```powershell
npm --prefix spine_runtime run build
npm --prefix spine_runtime run test:conversation
npm --prefix spine_runtime run test:browser
```

浏览器测试只需 5180 的演出页服务，不连接 Roomwave 服务或 MediaMTX。各页面实例各自持有本地会话，不再争用唯一远端演出连接。

当前单页回归覆盖：

- 四个新增场景通过真实 AIRI 解析和 c010 轨道执行；基本逐字场景保留原覆盖。
- 重复 ACT 的决定为一次 `apply`、两次 `keep-current`；手动重复时动画时间不归零。
- 完成后可重新播放同一反应；不同反应切换后新动作持续到其自身结束。
- 文字结束时反应仍在；neutral 清反应后文字继续。
- 默认思考被手动开心替换后，第一段普通文字不会清除开心。
- 新轮次中断旧反应，旧轮次迟到的生气信号不再执行。
- 只在测试响应内把 `delight` 换成近似名称，验证加载入口准确报错并阻止启用。磁盘素材不改动。
- 保留固定语音自然结束、中断回 idle 及组件卸载回归；启停覆盖改为本地暂停恢复，并检查不请求房间 API 或媒体服务。

测试输出 `c010-local-behavior.webm`、场景截图及 `stage-report.json`。机器检查播放时间、轨道与状态；录像用于人工评估动作衔接和突兀感。通过功能回归不等于所有动作组合或长时间演出已完成视觉与性能验收。
